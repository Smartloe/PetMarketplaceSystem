# 吉祥宠物商城前台 UI 去模板感重设计规格

- 日期：2026-04-06
- 项目：`/Volumes/有庭树/PROJECTS/PetMarketplaceSystem`
- 范围：前台商城第一轮体验重构
- 关联前端目录：`frontstage/pet_shop`

## 1. 背景与问题定义

当前前台已经具备基础浏览、登录、详情、个人中心等业务能力，但整体界面仍然呈现出较强的课程作业 / 通用模板气质，主要表现为：

- 首页使用大面积高饱和渐变、emoji 和通用功能卡片，品牌识别不稳定。
- 顶部导航和用户入口混用 emoji、链接层级偏多，像拼装组件而不是完整商城壳层。
- 商品列表信息密度低、视觉层级弱，登录前后的差异只体现在提示，不足以形成自然的“预览到解锁”体验。
- 登录、注册、用户中心更像后台表单页，不像消费型商城的账户流程。
- 详情页可用但缺乏清晰的购买决策路径，信任信息、主操作和补充信息没有形成优先级。
- 全局样式存在双轨问题：`src/assets/design-system.css` 提供了一套新变量，但 `src/assets/style.css` 仍保留大量旧模板样式，容易造成视觉不一致。

本轮目标不是推倒重做业务，而是在尽量复用现有图片、logo、接口和页面结构的前提下，把前台体验提升为“温柔、可信、克制、有消费感”的宠物商城界面。

## 2. 目标与非目标

### 2.1 本轮目标

- 去除明显的 AI 模板感、课程作业感和组件拼装感。
- 建立统一、稳定的前台视觉语言与文案语气。
- 强化游客态与登录态的体验差异，让“登录查看全部”更自然、更可信。
- 优化首页到列表到详情到登录的转化链路。
- 让用户中心从“资料编辑页”升级为“消费型账户中心”。
- 桌面端优先建立品牌感，同时保证手机端好用。

### 2.2 非目标

- 不更换 logo，不重做商品主图，不新增品牌插画体系。
- 不重做后台管理端。
- 不主动扩展后端业务能力，不新增复杂数据模型。
- 不在第一轮重做 `Favorites`、`Messages`、`Orders`、`ShoppingCart`、`AIPetExpert` 页面本体。
- 不引入新的前端框架或替换现有 Vue + Element Plus 技术栈。

## 3. 设计方向

### 3.1 总体气质

采用“A 为主，混一点 C”的方向：

- 主体气质为温柔精品感，强调陪伴、信任、克制和真实消费感。
- 混入少量清爽专业感，提升层级清晰度和信息效率。
- 整体避免幼态、花哨、网红促销页风格，也避免过度高冷的 SaaS 化界面。

### 3.2 视觉关键词

- 温暖但不甜腻
- 友好但不幼稚
- 精致但不奢华
- 克制但不单调
- 清楚但不生硬

## 4. 视觉系统

### 4.1 色彩

建立“暖米白 + 低饱和品牌色 + 稳定深色文字”的组合：

- 背景主色以暖白、奶油白、浅雾灰为主，减少大面积强渐变。
- 主强调色使用偏温暖的橙杏色或珊瑚色，承担主按钮和关键标签。
- 辅助色使用低饱和蓝绿，承担状态、辅助分类和信任信息。
- 风险、提醒、成功状态保留明确语义色，但整体降低刺激性。

视觉规则：

- 不再使用满屏高饱和彩色背景作为页面主基调。
- 渐变只用于局部氛围、按钮或弱装饰，不作为通栏主背景。
- 页面需要保留足够留白，让商品图片和关键信息成为主角。

### 4.2 字体与排版

- 保持中文环境下的清晰阅读，不引入激进标题字体。
- 标题层级更克制，依赖字号、字重和留白，而不是炫技特效。
- 正文保持较高可读性，减少过密行距和“海报式”大段标语。

排版目标：

- 首页更像精选导购页。
- 列表更像有秩序的目录页。
- 登录注册更像品牌入口页。
- 用户中心更像账户空间而不是后台表单。

### 4.3 图标与插图表达

- 去掉导航、功能卡片和按钮中的 emoji 表达。
- 全站统一替换为简洁线性或微填充图标。
- 尽量复用现有图片资源和 logo，不新增重资产插画。

### 4.4 组件外观

- 卡片圆角更柔和，但避免软塌塌的“儿童玩具感”。
- 阴影轻、浅、分层明确，以悬停抬升和结构层级为主。
- 按钮不再追求夸张渐变和强光感，改为更稳定的实色或轻渐变。
- 表单边框、聚焦态、错误态统一为消费产品风格，不呈现后台系统既视感。

### 4.5 动效

- 动效只用于帮助理解，不为“显高级”而存在。
- 保留导航悬停、卡片抬升、筛选展开、表单切换、登录后解锁反馈。
- 微动效持续时间控制在 150ms - 280ms。
- 遵守 `prefers-reduced-motion`，不依赖运动完成信息传达。

## 5. 信息架构与共享壳层

### 5.1 共享壳层目标

第一轮先建立统一的前台壳层，让用户在不同页面切换时始终感受到同一个商城，而不是多个拼装页面。

共享壳层包括：

- 头部导航
- 页宽与内容容器
- 页面节奏与留白系统
- 卡片、按钮、标签、输入框、空状态、提示状态
- 底部信息区

### 5.2 共享壳层原则

- 顶部导航更轻、更稳，优先突出品牌、核心入口、账户入口。
- 导航项目精简视觉噪音，减少图标与文案争抢注意力。
- 用户入口以“账户 / 登录状态”表达，不做夸张下拉菜单表演。
- 底部不再只是低价值链接堆叠，而是承担服务承诺、帮助入口与品牌收束。

## 6. 页面级设计方案

### 6.1 首页 `Home`

首页从“轮播 + 功能卡片”升级为“精选导购首页”，主要承担三个任务：

- 让用户快速理解这个站点卖什么、适合谁。
- 给游客足够真实内容预览，建立登录动机。
- 将用户导向商品列表、重点分类和可信商家内容。

首页结构建议：

- 首屏 Hero：品牌语、简短说明、主 CTA、次 CTA、现有视觉素材。
- 快捷入口区：按“宠物 / 用品 / 新手友好 / 同城优先”等方式做轻分类。
- 精选商品区：展示一组真实商品卡片，体现商城内容质量。
- 信任区：用具体信息替代空洞口号，如售后、配送、商家活跃、看宠流程。
- 辅助内容区：保留 AI 宠物顾问入口，但弱于购物主链路。

首页禁止事项：

- 不再使用大面积花哨炫彩背景作为主视觉。
- 不再使用 emoji 功能卡片作为平台特色表达。
- 不再堆叠没有数据支撑的营销口号。

### 6.2 顶部导航 `Header`

导航重构重点：

- 品牌左侧更稳定，logo 与品牌名组合更整洁。
- 中间主导航只保留真正高频且前台相关的入口。
- 账户入口根据登录状态切换语言和操作，不混用情绪化图标。
- 移动端菜单改为更明确的层叠结构，减少当前“整屏链接列表”的散乱感。

一级导航优先级：

- 桌面端一级导航优先保留“首页”“在售商品”“AI 宠物顾问”“购物车”。
- “收藏”“订单”“留言”不再与核心浏览入口并列展示，统一收纳到账户相关入口中。
- 移动端可保留同样的信息结构，但以分组方式展示，不做平铺长列表。

文案方向：

- “所有商品”可调整为更自然的“在售宠物 / 商城好物”之一。
- “登录/注册”改为更明确的“登录后查看完整内容”或“登录 / 创建账号”。

### 6.3 底部 `Footer`

底部承担品牌收尾而不是纯占位：

- 上半部分展示 2 - 3 条简洁服务承诺。
- 下半部分保留帮助与关于入口，但视觉更轻。
- 整体与头部形成风格闭环，不使用默认 Element Plus 链接堆叠感。

### 6.4 商品列表 `CommodityList`

列表页是本轮体验改造的核心页面之一。

目标：

- 让游客先看到真实内容，再意识到完整列表需要登录。
- 让登录后的用户明显感知到内容被解锁，而不是“看起来没变化”。
- 强化搜索、筛选、分类与商品卡片的层级。

结构方向：

- 页面顶部增加标题区，说明当前浏览范围与站点筛选逻辑。
- 左侧分类栏升级为更清晰的目录面板，视觉上弱于商品内容、强于纯文本列表。
- 右侧商品区改成更有导购感的商品卡片布局。
- 搜索框、结果计数、登录提示和筛选信息形成同一信息层。

游客态规则：

- 游客可看到精选商品预览和部分分类内容。
- 游客列表展示前若干项真实商品。
- 预览数量优先遵循后端返回的 `preview_limit`；若接口未返回该字段，则前端默认按 6 条处理。
- 超出部分通过柔和遮罩、锁定区块或“登录后查看全部在售内容”提示表达，不使用硬弹窗打断。
- 游客仍可进入商品详情，但在加购、收藏等动作上继续要求登录。

登录态规则：

- 登录成功后列表自动恢复完整数据。
- 页面上应提供明确的“已解锁全部内容”反馈，但不能像系统提示弹窗那样生硬。
- 分页、搜索、分类切换都以完整数据为基础，不再沿用游客裁切结果。

商品卡片信息优先级：

- 第一层：图片、名称、价格。
- 第二层：品类、年龄 / 规格、城市 / 商家等辅助决策信息。
- 第三层：销量、发布时间、店铺状态等补充信息。

### 6.5 商品详情 `CommodityDetail`

详情页目标是让用户更快做出判断与操作。

首屏优先级：

- 主图
- 标题
- 价格
- 关键说明
- 主操作按钮
- 信任标签

页面规则：

- 将“加入购物车”和“加入收藏”区分主次，不并排抢同等注意力。
- 信任信息改为更真实的购买辅助信息，而不是固定三枚模板标签。
- 商品详情和评价 Tab 保留，但视觉上更干净，避免像后台内容模块。
- 未登录用户在尝试关键操作时，提示语气应更自然，先说明价值再引导登录。

### 6.6 登录 `Login`

登录页定位为“进入完整商城体验”的入口，而不是单纯表单弹窗。

改造方向：

- 左右或上下双区块结构，保留现有图片资源做氛围图。
- 表单区加入简短价值说明，例如登录后可查看全部在售宠物、收藏、下单和管理订单。
- 验证码区域不再像临时补丁，而是融入表单节奏。
- 按钮、辅助链接、错误提示语气统一。

文案方向：

- 主按钮：“进入商城”或“登录查看完整内容”。
- 辅助文案强调利益点，不用“用户登录”这种纯系统命名。

### 6.7 注册 `Register`

注册页与登录页共用视觉语言，但强调“快速开始”而不是复杂开户。

规则：

- 与登录页共享背景、壳层、表单样式和节奏。
- 将字段说明、校验反馈和跳转链接做得更轻、更友好。
- 减少“红字报错堆叠”的表单感，把错误说明贴近字段本身。

### 6.8 用户中心 `UserCenter`

用户中心从“后台资料表单 + 地址表格”重构为“账户主页 + 信息编辑区”。

目标：

- 先让用户感受到这是自己的账户空间。
- 再提供资料、头像、地址等编辑入口。

结构方向：

- 顶部为个人摘要区，展示头像、用户名、账户状态和简洁描述。
- 下方分为资料设置区、地址管理区两个主要模块。
- 表格型地址展示可以保留数据能力，但视觉上更像卡片式地址管理。
- 主要按钮数量减少，编辑与保存的关系更清楚。

### 6.9 非本轮页面

`Favorites`、`Messages`、`Orders`、`ShoppingCart`、`AIPetExpert` 不作为第一轮重点重绘页面，但要至少继承新的全局壳层、按钮、字体、配色和头尾风格，避免与改造页面割裂。

## 7. 交互与文案原则

### 7.1 交互原则

- 每个页面只保留一个最强主操作，其他操作降级。
- 交互反馈更像消费产品，不像后台系统。
- 加载优先使用骨架屏、局部占位和温和提示，不使用满屏强打断。
- 空状态先给解释和建议，再给返回动作。
- 错误提示贴近当前操作，不只返回“请求失败”“暂无数据”。

### 7.2 文案原则

- 少喊口号，多给判断依据。
- 少用“火爆热卖”“限时抢购”“全网最低”等套路化促销文案。
- 用“适合新手家庭”“可预约到店看宠”“优先展示近期活跃商家”等更可信、更克制的表达。
- 全站语气保持像认真选宠顾问，而不是直播促销口播。

## 8. 响应式与可访问性

### 8.1 响应式原则

- 以桌面端为主建立品牌感和布局节奏。
- 手机端不做简单缩放，而是重排优先级。
- 移动端首屏必须优先看到搜索 / 分类、商品图片、价格和主操作。
- 复杂横向布局在小屏下拆成纵向块，但保持视觉一致性。

### 8.2 可访问性原则

- 交互元素保证足够点击面积。
- 颜色对比满足基础可读性。
- 图标按钮提供文本或辅助说明，不依赖纯图形理解。
- 焦点态可见，不只在 hover 下表达可点击性。
- 关键反馈文案不只依赖颜色区分。

## 9. 技术边界与实现约束

- 尽量复用现有 Vue 页面、路由和接口，不做整站重写。
- 不要求后端新增接口即可完成第一轮 UI 重构。
- 允许在前端新增轻量级共享组件、样式变量、图标封装和布局壳层。
- 允许重构 `src/assets/design-system.css` 与 `src/assets/style.css` 的职责边界，优先清掉旧模板样式污染。
- 保持现有登录、验证码、商品列表、详情和用户中心接口契约不变。
- 若实施中发现某个展示目标必须依赖额外字段，列为第二阶段或独立后端任务，不在本轮默认纳入。

## 10. 风险与控制策略

### 10.1 主要风险

- 旧全局样式与新页面样式相互覆盖，导致改一处坏多处。
- 列表页游客裁切逻辑与分页 / 搜索交叉后产生体验不一致。
- 登录后已解锁状态如果只靠数据变化而无明确反馈，用户仍会认为“没生效”。
- Element Plus 默认组件皮肤如果不统一包裹，最终仍会残留模板感。

### 10.2 控制策略

- 先收敛设计变量、共享组件样式和壳层，再改页面。
- 优先改感知层，不主动扩大业务层修改。
- 将游客态与登录态规则写成前端可实现的统一逻辑，不分散在多个页面临时判断。
- 对旧样式采取替换或收口策略，避免新旧风格长期并存。

## 11. 验证方式

### 11.1 自动验证

- 前端实现完成后执行 `npm run lint`。
- 前端实现完成后执行 `npm run build`。

### 11.2 手动验证

- 以游客身份访问首页、商品列表、商品详情，确认预览与登录引导自然可理解。
- 从登录页登录后跳转到商品列表，确认完整内容已经解锁且用户可感知。
- 在详情页验证未登录拦截、登录后加购 / 收藏、提示语气与跳转链路是否正常。
- 在用户中心验证资料读取、资料更新、头像上传、地址管理是否未被 UI 改造破坏。
- 在桌面宽度与手机宽度下分别检查头部、首页、列表、详情、登录、注册、用户中心是否无明显溢出和错位。

## 12. 验收标准

### 12.1 视觉与体验验收

- 用户第一次打开首页，不会认为这是通用 Vue 模板页。
- 全站不再出现 emoji 导航、拼装式功能卡片和高饱和模板背景主导界面。
- 未登录时能看到真实商品预览，并清楚理解登录后可查看更多。
- 登录后列表和详情体验明显更完整，用户能感知到“已解锁”。
- 登录、注册、用户中心更像消费型商城账户体验，而不是后台表单。
- 桌面端更有品牌感，手机端不显拥挤或难操作。

### 12.2 技术与实现验收

- 不破坏现有前台核心业务链路：浏览、登录、详情、加购、收藏、资料编辑、地址管理。
- 改造后前端仍可通过现有接口正常运行。
- 页面在常见桌面宽度和手机宽度下无明显布局溢出。
- 全站主按钮、卡片、输入框、提示语气和图标风格保持一致。
